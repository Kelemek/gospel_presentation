# Features & Functionality

Guide to core features and their implementation.

## Questions & Answers

Users can answer reflection questions added to profiles by editors:
- Questions added per subsection
- Answers stored in database (logged in) or sessionStorage (anonymous)
- Users can track answers across sessions
- Counselors can view aggregated responses

**Storage**: `user_answers` table (RLS protected)

## COMA Method

COMA = **C**ircumstances, **O**bedience, **M**otives, **A**pplication

The COMA template provides a structured framework for reflection:
- Pre-configured in `coma_templates` table
- Available to all users (RLS allows public read)
- Displayed in modal during profile usage
- Customizable by admins

**Status**: RLS policies fixed - now visible to all users including counselees

### Four Rules of Communication

When the exact phrase "Four Rules of Communication" (F, R, C capitalized) appears in profile content (titles, subsection content, or questions), it is rendered as a pill-style button. Clicking it opens a modal that lists the four rule headers only: Rule One - Be Honest; Rule Two - Keep Current; Rule Three – Attack the Problem, Not the Person; Rule Four – Act, Don't React. The modal content is static (no API). Same pattern as the COMA link: `GospelInlineHtml` / `injectGospelInlineMarkersInHtml.ts` flatten text per block (`p`, headings, table cells, `li` without a child `p`, or a sole wrapper `div`) and replace matches with mount spans via **DOM Ranges** so lists stay valid and references still match when rich text splits a verse across inline tags (e.g. bold book name); `FourRulesModal.tsx` lives in `gospel-admin/src/components/`.

## Scripture Modal

When users click a scripture reference, a modal displays the full text with these features:

- **Translation selector**: Choose from enabled translations (ESV and optionally KJV, NASB, LSB, NIV, NLT, CSB via API.Bible when configured and enabled in admin). In the scripture reader modal, translation and compare use the same **button + listbox** pattern as the pin control (not native `<select>`). Options are ordered by admin **display_order** in `translation_settings`, including the **Bible Translation** control in the table-of-contents menu (`TableOfContents.tsx`).
- **Compare feature**: A second menu (default label **Compare**) lets users pick another translation to view side-by-side
  - Compare translation appears on the left, main translation on the right
  - Each column shows scripture text plus the appropriate attribution
  - Works for both verse view and chapter context
  - Compare options exclude the current main translation
- **Verse view**: Single verse or verse range
- **Chapter Context**: Expands to show full chapter with highlighted verse(s)
- **Hover preview** (inline scripture pills in profile content): **`ScriptureHoverModal`** loads text from `/api/scripture` on **hover** (mouse, after a short delay) or **long-press** (touch). The popover uses **viewport-based width** (up to about **600px** on wide screens, less on phones). **Height** is capped by both a global max (~**720px**) and the **free space above or below the hovered reference** so the card stays next to the anchor; overflow **scrolls**. If a tall placement probe does not fit on either side, the popover **anchors to the roomier side** (below vs above) instead of vertically centering with full height (which used to pin the card to the top). Placement stays within the visible viewport.
- **Attribution**: Footer displays copyright/attribution per translation; when comparing, attributions appear in each column
- **Header title**: On narrow widths, the modal title truncates the **book name** (ellipsis) and keeps **chapter:verse** visible; full reference is in `title` and `aria-label` (so assistive tech and tests see the complete string)
- **Memorize**: **Memorize** (`data-tour="scripture-modal-memorize"`) sits in the reader toolbar row with **Verse** and **Chapter Context** and saves the passage to the local memorization list when text has loaded; disabled while loading, on error, if already saved, or if there is no text. See **Verse memorization** below.
- **Pin (local)**: **Pin** (`data-tour="scripture-modal-pin-color"`) is a compact **icon picker** on the **top** toolbar row beside **Compare** and **translation** (tap when the chevron shows). The menu lists **red**, **blue**, **green**, and **violet** 📌 pins only—**yellow** is not a menu choice; **there is no “none”** row; clearing uses the 📌 on the card or **Clear pinned passages** in the slide-out menu. **Yellow** is “last verse viewed”: passages that are not pinned with another tint show yellow on the control; closing without changing the picker advances yellow **only when** nothing else bookmarks that passage. **Red**, **blue**, **green**, and **violet** can repeat across different passages as bookmarks. Choosing a menu tint commits that bookmark color when you close the reader.
- **Study (Spurgeon)**: On profile pages with **`onOpenSpurgeonStudy`**, the reader calls **`GET /api/scripture/spurgeon-links`** for the open reference; **Study** (`data-tour="scripture-modal-spurgeon-study"`) appears in the toolbar **only when** at least one indexed public sermon matches. It opens the Spurgeon library modal with **By scripture** prefilled (see [02-BIBLE_AND_SCRIPTURE.md](02-BIBLE_AND_SCRIPTURE.md)). The modal does **not** show presentation subsection body HTML—only the verse text (and optional Chapter Context when chosen).

**Implementation**: `ScriptureModal.tsx` (compare state, fetch, layout) + `ScriptureModalToolbarMenu.tsx` (translation & compare menus) + `ScriptureModalPinPick.tsx` (toolbar pin control); reference splitting: `gospel-admin/src/lib/splitScriptureReferenceForHeader.ts`. Inline hover: `gospel-admin/src/components/ScriptureHoverModal.tsx`.

### Text highlights (local)

- Readers can select text in **main resource body content** (subsection and nested-subsection content blocks) to create highlights.
- Highlights are local-only (`localStorage` key `gospel-profile-highlights`), versioned, and scoped by profile slug + content block + text offsets.
- A **Highlights** trigger appears in the profile header (left of **Bookmarks**). The panel groups highlights by resource title, lists each quote + location (shown as **plain text**, with angle-bracket markup stripped for display and search), and supports **open/jump** and **delete** per highlight; a **debounced search** box under the panel title filters by quote text, location label, profile title/slug, and anchor/scope identifiers.
- Jumping to a highlight scrolls to the stored anchor and briefly emphasizes the saved text range.
- **Delete**: use the trash control in the Highlights panel, or **click/tap the highlighted text in the body** and confirm removal.
- Implementation: `profileHighlightsStorage.ts`, `profileHighlightVisibleText.ts` (shared offset stream: skip inline `data-gospel-mount` text; **`plainTextForProfileHighlightUi`** for panel rows + new saves), `HighlightsDropdown.tsx`, `ProfileContent.tsx`, highlight wrapping in `GospelInlineHtml.tsx` (`<mark data-resource-highlight-id>` with **one mark per DOM block**—`<p>`, headings, `li`, **TipTap-style nested `<div>` lines**, `blockquote`; avoids invalid wraps that Safari/WebKit show as thin edge-only bars; **injected HTML uses a `display:contents` `div` host** so `<p>`/blocks stay in-tree under `[data-highlight-scope]` in WebKit; `data-resource-highlight-active` when focused), **`globals.css`** for paint (`!important` fill + `box-decoration-break: clone` so multi-line wraps stay visible in dark mode/Capacitor), and scope metadata from `GospelSection.tsx`.

## Scripture pins (highlighted cards)

On profile pages, readers bookmark passages with tinted pins for visual wayfinding: **one yellow** slot (“last verse viewed”) plus **many** tinted bookmarks (**red**, **blue**, **green**, **violet**) that can reuse the same color on different passages. Only **one** pin per passage (changing tint replaces any prior pin there). Pins are **device-only** (`localStorage` JSON `v:2`); they are not written to Supabase. Older payloads (`v:1`, `byColor`) migrate on first load.

**First-load migration (localStorage)**: If there is nothing under `gospel-verse-pins-{profileSlug}` but the old **`gospel-scripture-progress-{profileSlug}`** key still exists from the earlier single-slot progress store, **`loadVersePins`** copies that passage into the **yellow** slot, persists the new key, and removes the legacy key **only after** a successful verified write (so quota / storage failures cannot delete the legacy key before the migration is durable). Invalid legacy JSON is ignored (the stale key stays until cleared manually).

**Legacy note**: The `last_viewed_scripture` column and `GospelProfile.lastViewedScripture` in types remain in the schema and API for older data/admins but the **presentation viewer** no longer uses them for highlights or sync.

### Resources dropdown (public templates)
- The main page sidebar shows a Resources menu with public templates.
- Admins can create categories and assign templates to them (Admin → Settings → Resources dropdown order). They can also add a **Spurgeon library** row (at most one): it opens an in-app modal to search public Spurgeon sermon profiles by keyword or by Bible reference (`SpurgeonSermonsModal`, APIs under `/api/spurgeon/*`). The sermon list uses Postgres **`spurgeon_public_sermons_page`** (`sql/migrations/20260504_spurgeon_public_sermons_page.sql`; apply **`sql/migrations/20260505_spurgeon_public_sermons_page_alpha_search.sql`** for punctuation-insensitive title search, e.g. `davids` matches `David's`) for correct pagination at full corpus size; ordering is **A–Z** by title after stripping **`Sermon N.`** / **`Sermon N-M.`** (same as `spurgeonSermonTitleForModalDisplay` in `sortBySpurgeonSermonSlug.ts`). **`GET /api/spurgeon/by-reference`** sorts multiple hits the same way. In the modal **By scripture** field, a **full book name** (e.g. `John`) or **prefix** (e.g. `rom`, `1 joh`, `jhn`) lists every indexed sermon that cites **any passage in those matched book(s)**; a debounced request still applies. Parsed verse references (e.g. `John 3:16`) keep precise passage matching. Stored `title` values in `profiles` are unchanged. The modal backdrop uses **`100dvh`**, horizontal and top **`env(safe-area-inset-*)`**, and at least **48px** bottom inset (`max` with `env(safe-area-inset-bottom)`) so the pagination bar clears Android gesture / 3-button navigation when the WebView reports no bottom safe area. Modal inputs use **`text-base`** (16px) so Mobile Safari does not auto-zoom on focus; the overlay uses **`overflow-x-hidden`** and the dialog panel **`min-w-0`** to limit horizontal shift.
- Categories expand on click to show their templates; top-level items, the Spurgeon row, and categories can be reordered by drag-and-drop.
- Sermon templates imported from CCEL use slugs `sg` + five digits, `is_template: true`, default `is_public: true` (discoverable in the Spurgeon library and as `/sg…` profiles), and `include_in_resources_menu: false` so they are not auto-listed as generic resource templates. Re-import keeps `is_public` true for CCEL sermon profiles. Each sermon’s **title** comes from ThML `<div1 title="…">`. Outline is inferred primarily from `<p class="Body">` text; when a sermon has no Body paragraphs, the same logic uses plain `<p id="…">` and `<p class="Centered">` so odd ThML layouts still import (these volumes rarely use inner `<head>` / `<div2>` per point). **Catalog `N`** for slug `sg…` uses **`(No. N)`** in the sermon body when present, else **`Sermon N.`** at the start of the div1 **`title`** (exposition sermons often omit the body line). If neither yields N, that `div1` is skipped (no guessed `sg…` slug), so later volumes cannot overwrite unrelated catalog profiles. Some CCEL volumes are **incomplete** and omit entire sermons from the XML; that sequence gap cannot be fixed by re-import. Parse-only (fetch + parse, no Supabase): `npm run import-spurgeon -- --parse-only --url <volume.xml>`; optional `--limit N` or `--slug sgNNNNN` (full-volume parse when `--slug` is set). Targeted re-import: `npm run import-spurgeon -- --url <volume.xml> --slug sgNNNNN` parses the whole volume then upserts only that slug. Fill **all** Met Tab sermons missing from the DB (each volume fetched once; only inserts/updates slugs not already present): `npm run import-spurgeon-missing` from **`gospel-admin/`**; add `--dry-run` to list what would import. After changing Roman **I.** outline heuristics in `ccelSermonHtml.ts`, repair stored sermon JSON (no CCEL fetch) with `npm run fix-spurgeon-roman-one-gospel-json` from **`gospel-admin/`** (`--dry-run`, optional `--limit N`, optional `--slug sg#####` or `--slug 3252` for one sermon); re-splits `<p>…</p>` blocks using the same major-outline rules and rebuilds **`spurgeon_passage_index`**. For ThML or non-outline fixes, use normal **`npm run import-spurgeon`** / **`import-spurgeon-missing`** against CCEL. Bulk-set existing `sg#####` profiles public: `npm run spurgeon-set-all-public` (optional `--dry-run`). Covers CCEL `sermons01.xml`–`sermons63.xml` (catalog **1–3563**; **423–426** never in XML; numbering skips **1451–1452**, **1876**, **2000**). Batch gaps (one fetch per CCEL volume): `npm run import-spurgeon-gaps -- --gaps 67,82,92` (skips numbers with no volume or no matching `div1` in XML); add `--dry-run` to print only. The importer splits on **major outline** (Roman **II.–XIV.** always; Roman **I.** only when the following word looks like a homiletical head—e.g. **First**, **So**, **Therefore**, **JESUS**—so pronoun **I.** in *“I. will never leave you.”* does not start a new section; **FIRST./SECOND./…**), merging Body paragraphs until the next major marker. Numbered lines (**1.** through **99.** style: one or two digits, a period, space, then text—e.g. **3. Then again…**) under a major head become **`nestedSubsections`**; text before the first such line stays in the parent subsection `content` (`ccelSermonHtml.ts`). ThML **`scripRef`** is expanded to **canonical reference text inside that HTML** (e.g. `Rom 8:28` → `Romans 8:28`) so **`injectGospelInlineMarkersInHtml`** can render **clickable** references that open the scripture modal (`GospelInlineHtml.tsx`). The importer **does not** populate subsection **`scriptureReferences`** for sermon bodies; **`spurgeon_passage_index`** rows still come from **`passage=`** on **`scripRef`** / **`scripCom`**, with references normalized before canonical keys (`ccelSermonHtml.ts`). On the reader, parent **`content` appears before nested sub-points**; other profiles may still use subsection scripture pills where editors added them (`GospelSection.tsx`).
- **Backfill `spurgeon_passage_index` from stored sermon HTML**: If index rows are missing references that already appear in `gospel_data` (plain text in HTML, scripture cards, or reflection Q/A), run from **`gospel-admin/`**: `npm run backfill-spurgeon-passage-index -- --dry-run` (preview) or omit `--dry-run` to insert missing keys only (uses `SUPABASE_SERVICE_KEY`; same as `npx tsx scripts/backfill-spurgeon-passage-index-from-profiles.ts`). Logic: [`passageKeysFromGospelData.ts`](gospel-admin/src/lib/spurgeon/passageKeysFromGospelData.ts) → same **`passageKeysFromRefs`** / range expansion as CCEL import.

## Text size (presentation site)

- On **`[slug]`** gospel profile pages, the slide-out **Table of Contents** drawer lists **Resources**, **Text size**, **Print** / **Bible Translation**, **Memorize** (below **Bible Translation**), section links, then profile summary and pinned passages; **Save my data** / **Restore my data** appear **above** **Login** / **Dashboard** (`MenuLocalDataBackup.tsx`, then `SidebarAuthNav.tsx`). **Login** is hidden on **Capacitor** native builds (same as before).
- **Closing the drawer**: **Mobile** uses a transparent full-viewport layer (`z-40`) under the drawer so tapping outside closes it. **Desktop** closes when the pointer **leaves** the slide-out panel **or** when you **click** the main content area below the header (`ProfileContent` attaches the dismiss handler to the flex-growing content column so “click away” works after guided tours and matches reader expectations).
- In the sidebar below **Resources**, a **Text size** dropdown matches the Resources styling and offers **Normal**, **Larger**, and **Largest**.
- The choice is saved in `localStorage` (`gospel-profile-text-size`) and scales root font size on the main site via `TextSizeContext`, `ApplyTextSize`, and `html.text-size-*` classes in `globals.css`.
- **`/admin` routes are excluded**: text scaling is not applied on admin pages so the admin UI stays at default size.

## Local data backup (slide-out menu)

- **Save my data** saves one **JSON** file of **this browser’s** gospel data: bookmarks, **text highlights** (`gospel-profile-highlights`), memorized verses, pinned passages (per-profile keys), reflection answers, preferred translation, theme, text size, memorize listen speed, and first-visit welcome dismissal (`gospelLocalUserDataBackup.ts`). **Capacitor iOS** is unchanged: **Web Share** with a **file only** (no extra text item). **Capacitor Android** writes the file to app cache with **`@capacitor/filesystem`** then opens the native share sheet via **`@capacitor/share`**. The shared file uses a **`.txt`** extension so Android treats it as **`text/plain`** and the system chooser usually lists more destinations (including **Files**); content is still the same JSON. After saving, **swipe up** on the share sheet for the full app list if **Files** is not on the first row. (Requires a **new Android store build** after `cap sync`; the JS only `import()`s those plugins on Android so older **iOS** binaries from the store still work without shipping a new iOS build.) Fallback: `<a download>` with delayed blob URL revoke. On the **web**, the usual download link is used.
- **Restore my data** picks a backup file, asks for **confirmation**, writes only allowed keys into **`localStorage`**, then **reloads** the page so the UI picks up the restored state. On profile pages, while the OS file picker is open, the slide-out does **not** auto-close from desktop **mouse-leave** (so the hidden file input stays mounted until you choose or cancel—fixes Edge and similar browsers).
- **Not included**: admin session (`gospel-admin-auth`), card vs list admin view (`gospel-view-preference`), offline **profile HTML cache** keys (`gospel-profile-{slug}` blobs), and **`sessionStorage`**. Treat backup files as **private** (answers and memorized verse text can appear in JSON). Use backups on the **same site** (origin) they were created on.

## Verse memorization (presentation profile pages)

- **Add from scripture modal**: When the **Scripture** modal is open (`ScriptureModal.tsx`), **Memorize** beside **Verse** / **Chapter Context** saves the current passage (reference + plain text + selected translation) to **`localStorage`** (`gospel-memorization-verses` via `verseMemorizationStorage.ts`). HTML and verse markers like `[16]` are stripped before storage. Duplicates (same reference + translation) are rejected; success uses the standard alert modal. The modal opens on **Verse** (not Chapter Context). **Study** (Spurgeon) only appears when that passage has indexed sermon matches; see the scripture modal bullets above.
- **Add verse (menu)**: With **Memorize** expanded, **+ Add** opens a picker (`AddMemorizedVerseModal.tsx`): the modal title reads **Pick Chapter** until a chapter is chosen, then **Pick Verse Range** while picking verse(s). Old/New Testament tabs, book list with chapters, then verses for the chosen chapter. Pick a single verse or a verse range (second tap), then **Add**; text is loaded via **`GET /api/scripture`** using the **same Bible translation** as the app’s current preference (`TranslationContext`). Book/chapter/verse **structure** (66-book Protestant canon, verse counts per chapter) is **embedded in the client** (`bibleCanonStatic.ts`, built from KJV-aligned JSON via `scripts/generate-bible-canon-from-kjv.mjs`)—no API key required for the picker.
- **Menu list**: In the slide-out **Menu**, **Memorize** (`MemorizeDropdown.tsx`, **below Bible Translation**) expands to show saved verses grouped by **Learning** / **Practicing** / **Mastered** (`getMasterLevel`: fewer than 3 completed sessions → Learning; 3–8 → Practicing; 9+ → Mastered). Rows match the **Bookmarks** list pattern: **tap the verse row on the left** to open practice; **trash** on the right **removes** the verse (confirm modal).
- **Practice session** (`MemorizationPracticeSession.tsx`, `MemorizeListenControlsDialog.tsx`): The **saved reference** is shown **at the end of the verse line** and is part of what you memorize. **Listen** in the **modal header** opens the **Read aloud** sub-dialog: **play**, **pause**, **Repeat**, and **read-aloud speed** (all shown together). On **`[slug]`** profile pages, **Study** can appear **to the right of Listen** when **`GET /api/scripture/spurgeon-links`** finds indexed sermon matches for the saved reference (same rule as **Study** in `ScriptureModal`); tapping it **closes the practice overlay** (same persistence as **Close** when mid-session) and opens the **Spurgeon sermons** modal on **By scripture** (`data-tour="memorize-practice-spurgeon-study"`). During **typing rounds**, use that **header** control only. **ESV** uses **`GET /api/scripture/audio`** (Crossway passage MP3). **KJV, NASB, LSB, NIV, NLT, CSB** use the device **speech synthesizer** to read the **saved verse text and reference** (same string as the intro line; API.Bible only exposes full-chapter streaming audio, not verse ranges—see [02-BIBLE_AND_SCRIPTURE.md](02-BIBLE_AND_SCRIPTURE.md)). With **Repeat** on, the same read-aloud **loops** with a short gap between each play; turn it off to stop after the current play. **Start practice** or closing the session clears listen/repeat. **Start practice** then asks **Type mode**, **Word mode**, or **Reorder mode** (same five rounds: **Reorder** shuffles more clause-sized chunks each round—verse parts plus **book**, **chapter**, and **verse** as separate draggable chips when the reference parses; a **:** appears **between** chapter and verse (not its own chip)—and uses drag-and-drop to restore reading order; see `MemorizationReorderPanel.tsx` (fine-pointer desktop uses native HTML5 drag; **touch / Capacitor** uses pointer-driven reorder when **`(hover: none)`**, **`(any-pointer: coarse)`**, or **`navigator.maxTouchPoints > 0`**: movable chips use **`touch-action: none`** so the scrollable practice column does not capture the gesture, plus a **short hold** (~110ms)). In **Reorder mode**, hold **Hint** (like Type/Word) to temporarily show the correct phrase in the first section that is still wrong; release to hide it—no automatic swaps. For Type/Word, five rounds with blanks (**Word mode** uses up to **eight** **word** choices sized to each label (wrapped, centered rows) when there are enough distinct words, and up to **four** **digit** choices for number blanks—extra digit options are random digits **not** used in the passage when needed—instead of the keyboard). On intro, a **round** dropdown (options Round 1–5) chooses which **typing round** to begin at (default **Round 1**; **Start over** resets to Round 1); the session then continues in order through **round 5** (between-round **Repeat** / **Next** unchanged from starting at round 1). **Tokens** are built in `memorizationPracticeUtils.ts`: verse **words** use first-letter blanks; the **reference** adds **word** tokens (e.g. book name), **one blank per digit**, and **colon / dash / other punctuation** shown in place but **never** typed. Starts with the full line (verse + reference), then **Start practice** begins five rounds with an increasing share of **typable** tokens hidden (20% … 100%). Which tokens are blanked is randomized **per practice run**; **Repeat this round** / **Next round** keep the same blanks for that run. For **word** blanks, type the **first letter** (case-insensitive); for **digit** blanks, type that **digit**; the hidden input uses **`inputMode="numeric"`** when the current blank is a digit so mobile keyboards emphasize numbers. A nearly invisible **text field** stays in the DOM from intro through practice; **Start practice**, **Repeat this round**, and **Next round** use **`flushSync` + `focus()`** in the same tap handler so **iOS Safari and Capacitor WebView** treat focus as user-initiated and show the **system keyboard**. The practice panel adds **bottom padding** from **`window.visualViewport`** when the keyboard shrinks the visible area. The **active blank** is scrolled into view in the practice column whenever the current blank or round changes (**`scrollIntoView`** on non-Android; on **Android**, **`scrollTop`** is adjusted only as much as needed—**nearest** edges in `memorizationScrollIntoPractice.ts`, not full vertical centering—so IME + small viewport height does not clamp scroll to the **bottom** of a long verse; **new rounds** also reset the column **`scrollTop` to 0** on Android before focusing). On **Android**, the hidden IME **`<input>`** is **`fixed`** at the bottom of the viewport (sibling of the verse **`overflow-y-auto`** column, not inside it) so the browser does not **scroll the verse column to keep a top-anchored focused field in view** on wrong letters. A second pass uses **`window.visualViewport`** to **nudge** the column with **`scrollTo`** (**`behavior: 'smooth'`** when motion is allowed, **instant** when **prefers-reduced-motion**). **Android** (user-agent check in `memorizationViewportPlatform.ts`) always uses an **instant** nudge and **`requestAnimationFrame`**-coalesced **`visualViewport`** listeners for bottom inset, plus a **slightly longer** debounce before the keyboard-triggered re-nudge, so IME animation does not stack overlapping smooth scrolls; **iOS** behavior is unchanged when motion is allowed. The blank stays **inside the visible band** with extra clearance above the soft keyboard (tunable `MEMORIZE_EXTRA_GAP_ABOVE_KEYBOARD_PX` plus **bottom padding** from the viewport inset). The scroll runs again (debounced) when the keyboard **resizes** the viewport. **Hint** is in the **modal header** (next to **Close**) during practice so it stays visible when you scroll the verse; the button uses **capture-phase** `touchstart` / `pointerdown` (`passive: false` on touch) so a tap does not **blur** the field when the keyboard is up; on the **verse** area, **`touchstart` + `preventDefault`** (`passive: false`) runs **only** when the hidden field is already focused (keyboard up) so a tap does **not** dismiss the keyboard; starting a scroll **on the verse** while focused is not possible (scroll from the instruction / round row above the verse, or dismiss the keyboard first). **Mouse/pen** use **pointerdown** capture. When the field is **not** focused, **touch** can scroll the panel, and a **tap** (no meaningful **touchmove** past ~12px) calls **`focus()` synchronously on `touchend`** so **iOS** restores the keyboard. After releasing **Hint**, the field is **refocused** so the soft keyboard stays up or returns. Three wrong letters in a row for the same blank auto-reveal that word. **Hint**: hold the **Hint** button to temporarily peek at still-hidden words in order (italic blue styling): the **first** blank appears immediately, then **one more blank every second** while you keep holding; release to hide them again—keyboard input is ignored while the hint is held. After rounds 1–4 complete, **Repeat this round** and **Next round** appear in a **footer** at the bottom of the same modal while the verse stays on screen, with a **random affirmation** above the buttons (`memorizationEncouragementMessages.ts`: treasuring God’s Word in the heart, perseverance). After **round 5**, a **random congratulation** message is shown (same module) before **Done**; completing round 5 records a practice session (wrong attempts, correct keystrokes), clears any **in-progress** payload for that verse, and updates stats in localStorage. **In-progress practice** (`inProgressPractice` in `verseMemorizationStorage.ts`) is saved to the same verse row when you finish typing rounds 1–4 (before **Next** / **Repeat**), when you tap **Next round** / **Repeat this round** / **Start practice**, and when you **close** the modal during a typing round—reopening **Practice** resumes with the same **session seed** so blanks stay consistent; the payload includes **`practiceMode`** (`type`, `word`, or `reorder`) so a session interrupted in **Word mode** (or **Reorder mode**) does not reopen in **Type mode**. **Start over** in the modal header clears that saved progress. **Learning** / **Practicing** / **Mastered** still use only **completed** five-round sessions (`practiceSessions` with `completed: true`). **Escape** closes the **Read aloud** dialog if it is open, otherwise closes the practice overlay (and persists mid-round state the same way as **Close**); body scroll is locked while the session is open.
- **Tutorial** (**Help** → **Verse memorization**): Opens a scripture card, saves with **Memorize** in the reader (toast OK uses `data-tour="alert-modal-ok"`), closes the reader, opens **Menu** → **Memorize**, explains the list, starts practice from the **verse row**, walks **Start practice** → **Choose practice mode** (`data-tour="memorize-practice-mode-picker"` with **Type** / **Word** / **Reorder** buttons), then continues in **Type mode** for **Listen** and the read-aloud modal (**Play**/**Pause**, **Repeat**, **Speed**, close via `data-tour="memorize-listen-open"` … `memorize-listen-close`) when those controls are shown (otherwise the tour skips that block), continues with guided typing (round 1 preview), closes the session, then removes that verse with the **trash** control and confirm (`tryStartMemorizeTourAfterNavigation` on `/default` when starting from another profile).

## Native app (Capacitor)

The app is wrapped for iOS and Android via Capacitor (WebView loads the deployed site).

- **Tutorial navigation**: Scripture-reader tour jumps to `/default` and the full-walkthrough **thank-you** return to the stored profile slug use **`router.push`** on native (`CapacitorProfileHelpTourNavigation` in `layout.tsx` registers with `scriptureReaderTourNavigation.assign` in `profileHelpTours.ts`) so those moves stay in the WebView instead of opening the system browser.

- **Splash screen (iOS)**: On launch, the iOS app shows a centered app icon on a solid background (Launch Screen) and keeps it visible until the web app has loaded. This avoids a black screen between the system launch screen and the first painted content. Implemented with `@capacitor/splash-screen` (`launchAutoHide: false`) and `SplashScreenController` calling `SplashScreen.hide()` once the app is ready; the launch screen is defined in `ios/App/App/Base.lproj/LaunchScreen.storyboard` and uses the `LaunchIcon` image set (same graphic as the app icon). Changing the launch screen or splash behavior requires a **native rebuild** (e.g. `npx cap sync` then build in Xcode).
