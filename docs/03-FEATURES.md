# Features & Functionality

Guide to core features and their implementation.

## Questions & Answers

Users can answer reflection questions added to profiles by editors:
- Questions added per subsection
- Answers persist in the browser only (IndexedDB via `gospelClientStorage.ts`, key prefix `gospel-answers-{slug}` in `GospelSection.tsx`)
- Answer `<textarea>` and **Save Answer** use **at least 16px text on small viewports** (`text-base sm:text-sm`) so **iOS Safari** is less likely to auto-zoom on focus. After a successful save we **blur the active control** and apply a **one-pixel scroll nudge** so WebKit can restore the visual viewport; the textarea’s **`onBlur`** runs the same nudge when leaving the field without saving
- Older databases may still have a `saved_answers` column on `profiles`; the app does not write answers back to the database

**Storage**: browser IndexedDB via `gospelClientStorage.ts` (per profile slug); not synced to Supabase

## COMA Method

COMA = **C**ircumstances, **O**bedience, **M**otives, **A**pplication

The COMA template provides a structured framework for reflection:
- Pre-configured in `coma_templates` table
- Available to all users (RLS allows public read)
- Displayed in modal during profile usage
- Customizable by admins

**Status**: RLS policies allow appropriate read access for presentation use.

### Four Rules of Communication

When the exact phrase "Four Rules of Communication" (F, R, C capitalized) appears in profile content (titles, subsection content, or questions), it is rendered as a pill-style button. Clicking it opens a modal that lists the four rule headers only: Rule One - Be Honest; Rule Two - Keep Current; Rule Three – Attack the Problem, Not the Person; Rule Four – Act, Don't React. The modal content is static (no API). Same pattern as the COMA link: `GospelInlineHtml` / `injectGospelInlineMarkersInHtml.ts` flatten text per block (`p`, headings, table cells, `li` without a child `p`, or a sole wrapper `div`) and replace matches with mount spans via **DOM Ranges** so lists stay valid and references still match when rich text splits a verse across inline tags (e.g. bold book name); `FourRulesModal.tsx` lives in `gospel-admin/src/components/`.

## Scripture Modal

When users click a scripture reference, a modal displays the full text with these features:

- **Translation selector**: Choose from enabled translations (ESV and optionally KJV, NASB, LSB, NIV, NLT, CSB via API.Bible when configured and enabled in admin). In the scripture reader modal, translation and compare use the same **button + listbox** pattern as the pin control (not native `<select>`). Options are ordered by admin **display_order** in `translation_settings`, including the **Bible Translation** control in the table-of-contents menu (`TableOfContents.tsx`).
- **Compare feature**: A second menu (default label **Compare**) lets users pick another translation to view side-by-side
  - Compare translation appears on the left, main translation on the right
  - Each column shows scripture text plus the appropriate attribution
  - Works for both verse view and chapter context
  - Compare options exclude the current main translation
- **Verse / chapter toggle**: A single control (`data-tour="scripture-modal-verse-chapter-toggle"`) shows **Chapter** while you are on verse view (tap to load full chapter with highlighted verse(s)) and **Verse** while chapter context is shown (tap to return to the passage only). **Chapter-only** scripture cards (e.g. M'Cheyne reading plan refs like `Genesis 1` with no verse) open **already in chapter view** so Listen and full-chapter text are available without an extra tap. It uses a **fixed width** so the label does not shift between **Chapter**, **Verse**, and **Loading…**.
- **Previous / Next / swipe**: Header ◀ ▶ and **horizontal drag on the modal scroll area** (passage, attribution, and the rest of the scrollable pane — touch or **mouse click-and-drag** on desktop) move through **scripture cards in the current resource** (starred favorites when the profile has any, otherwise all cards in document order). Only after **Bible Reader** or the header **reference picker** does navigation step by **verse or chapter within the chosen book** ([`biblePassagePickerNavigation.ts`](gospel-admin/src/lib/biblePassagePickerNavigation.ts), `pickerNavigation` in [`ProfileContent.tsx`](gospel-admin/src/app/[slug]/ProfileContent.tsx)). Vertical scrolling in that pane still works when the gesture is mostly vertical (direction lock). Horizontal drag follows the pointer **1:1** (Mail-style): the current content moves with your finger or cursor and the next/previous slot is revealed underneath; releasing past **half the pane width** completes the slide-off, fetches the new passage, then the new text slides in from the opposite edge. The scroll area shows a **grab** cursor on desktop when navigation is available. In **compare** mode, both translation columns slide together. Header ◀ ▶ are unchanged. With **`prefers-reduced-motion`**, swipe navigation stays instant (no slide animation).
- **Hover preview** (inline scripture pills in profile content): **`ScriptureHoverModal`** loads text from `/api/scripture` on **hover** (mouse, after a short delay) or **long-press** (touch). The popover uses **viewport-based width** (up to about **600px** on wide screens, less on phones). **Height** is capped by both a global max (~**720px**) and the **free space above or below the hovered reference** so the card stays next to the anchor; overflow **scrolls**. If a tall placement probe does not fit on either side, the popover **anchors to the roomier side** (below vs above) instead of vertically centering with full height (which used to pin the card to the top). Placement stays within the visible viewport.
- **Attribution**: Footer displays copyright/attribution per translation; when comparing, attributions appear in each column
- **Header title**: On narrow widths, the modal title truncates the **book name** (ellipsis) and keeps **chapter:verse** visible; full reference is in `title` and `aria-label` (so assistive tech and tests see the complete string)
- **Memorize**: **Memorize** (`data-tour="scripture-modal-memorize"`) sits in the reader toolbar row beside the **verse/chapter toggle** and saves the passage to the local memorization list when text has loaded; disabled only when already saved (tapping while loading, on error, or before text arrives shows an alert). See **Verse memorization** below.
- **Pin (local)**: **Pin** (`data-tour="scripture-modal-pin-color"`) is a compact **icon picker** on the **top** toolbar row beside **Compare** and **translation** (tap when the chevron shows). The menu lists **red**, **blue**, **green**, and **violet** 📌 pins only—**yellow** is not a menu choice; **there is no “none”** row; clearing uses the 📌 on the card or **Clear pinned passages** in the slide-out menu. **Yellow** is “last verse viewed”: passages that are not pinned with another tint show yellow on the control; closing without changing the picker advances yellow **only when** nothing else bookmarks that passage. **Red**, **blue**, **green**, and **violet** can repeat across different passages as bookmarks. Choosing a menu tint commits that bookmark color when you close the reader.
- **Study (Spurgeon / devotions / Calvin / Matthew Henry)**: On profile pages with **`onOpenSpurgeonStudy`**, the reader calls **`GET /api/scripture/spurgeon-links`** for the open reference; **Study** (`data-tour="scripture-modal-spurgeon-study"`) stays in the toolbar and is **enabled** when at least one indexed sermon, Morning & Evening day, Calvin commentary book, or Matthew Henry commentary book matches; otherwise it is **greyed out (disabled)**. When enabled, **Study** opens the unified study library modal (`SpurgeonSermonsModal`) with **By scripture** prefilled; results are sectioned **Sermons**, **Morning & Evening**, **Calvin commentaries**, and **Matthew Henry commentaries** (see [02-BIBLE_AND_SCRIPTURE.md](02-BIBLE_AND_SCRIPTURE.md)). The scripture modal does **not** show presentation subsection body HTML—only the verse text (and optional full-chapter context from the verse/chapter toggle when chosen).
- **Word study (STEP Bible)**: Toolbar toggle label is **Greek**, **Hebrew**, or **Aramaic** for the open verse (`data-tour="scripture-modal-word-study"`). Opens an overlay on the reader’s verse pane (not a separate full-screen page) with original-language tokens (TAGNT/TAHOT + TBESG/TBESH lexicons). Works with any enabled English translation; disabled in chapter context. Tap a word for a floating Strong’s definition sheet (`ScriptureWordStudyModal.tsx`, `ScriptureWordStudyPanel.tsx`, `GET /api/scripture/word-study`, `GET /api/scripture/lexicon`). See [02-BIBLE_AND_SCRIPTURE.md](02-BIBLE_AND_SCRIPTURE.md).
- **Listen (ESV only)**: When the selected translation is **ESV** and passage text has loaded, a **Listen** control (`data-tour="scripture-modal-chapter-listen"`) appears in the **top header row immediately left of Share**. It uses the same speaker icon as profile **Listen**, opens **`MemorizeListenControlsDialog`** with **`presentation="floating"`** (**Play/Pause** and **speed** on one row; no Repeat; **no dimmed backdrop**—same near-top placement as profile header Listen so you can scroll and read the passage while controls stay visible), and streams passage audio via `GET /api/scripture/audio` (Crossway ESV MP3): **verse-level** in verse view (e.g. `John 3:16`), **chapter-level** when chapter context is on. While audio plays, the scroll pane **drifts continuously** in sync with playback (time-integrated each animation frame, proportional through the full scroll range until the attribution footer reaches the bottom of the pane). Implementation: `advanceScriptureListenIntegratedPlaybackTime`, `computeScriptureListenProportionalScrollTop`, `useChapterStreamingAudioListen` `autoScroll`. After **Play**, when a track finishes the reader **auto-advances** with the same logic as header **Next** / swipe (next scripture card, starred favorite, or picker verse/chapter step) and **continues playing** until **Pause**, the last available passage, or an error. On the **M'Cheyne** plan (`mchy`) with **ESV** selected, **Play** queues that day’s readings (Family then Secret, with chapter ranges expanded the same way as the cards) in order, **updates the open chapter in the reader** as each track starts, and **stops when the day’s playlist ends** (it does not auto-advance to the next plan day). Each playlist chapter change also updates the profile **scripture-card navigation index** so **◀ ▶** / swipe after listening advance to the next card on the page (e.g. the next plan day), not back to the second reading on the same day. Hidden for KJV, NASB, LSB, NIV, NLT, CSB. Available on **iOS and Android** native apps (unlike profile header Listen, which uses device speech and is hidden on Android).
- **Share passage**: Header control (`data-tour="scripture-modal-share"`) shares the **visible** primary-column passage (verse or full chapter when chapter context is on) as plain text, including the selected translation’s display name, plus a deep link to **`/{profile-slug}?scriptureRef=…`** on the **same resource** you are reading (optional `translation` and `scriptureView=chapter`) that opens the scripture reader when followed. Uses the same native share sheet / Web Share / clipboard fallback as **Share this resource** on profile pages (`shareScripturePassage.ts`, `scriptureModalShareUrl.ts`); does not include the compare column.
- **Hide verse numbers**: **Long-press** (~1s) anywhere in the scripture modal **scroll area** (passage, attribution, compare columns, etc.) opens a confirm dialog to **hide** or **show** inline verse number markers. The choice persists per browser in **`localStorage`** (`gospel-scripture-show-verse-numbers`, included in local user-data export/import). Chapter highlight boxes for the selected verse(s) remain when numbers are hidden.

**Implementation**: `ScriptureModal.tsx` (compare state, fetch, layout, share) + `ScripturePassageText.tsx` + `ScripturePassageSwipeLayer.tsx` + `usePassageSwipeNav.ts` + `scripturePassageHtml.ts` + `scriptureVerseNumbersPreference.ts` + `ScriptureModalChapterListen.tsx` + `useChapterStreamingAudioListen.ts` + `shareScripturePassage.ts` + `scriptureModalShareUrl.ts` + `ScriptureModalToolbarMenu.tsx` (translation & compare menus; portaled listboxes open **upward** from the trigger when opening downward would leave the panel off the bottom of the viewport) + `ScriptureModalPinPick.tsx` (toolbar pin control) + `ScriptureWordStudyModal.tsx` / `ScriptureWordStudyPanel.tsx` (STEP Bible word study); reference splitting: `gospel-admin/src/lib/splitScriptureReferenceForHeader.ts`. Inline hover: `gospel-admin/src/components/ScriptureHoverModal.tsx`.

### Text highlights (local)

- Readers can select text in **main resource body content** (subsection and nested-subsection content blocks) to create highlights.
- Highlights are local-only (IndexedDB key `gospel-profile-highlights` via `gospelClientStorage.ts`), versioned, and scoped by profile slug + content block + text offsets.
- A **Highlights** trigger appears in the profile header (**left of Bookmarks**, **right of Listen**). The panel groups highlights by resource title, lists each quote + location (shown as **plain text**, with angle-bracket markup stripped for display and search), and supports **open/jump** and **delete** per highlight; a **debounced search** box under the panel title filters by quote text, location label, profile title/slug, and anchor/scope identifiers.
- Jumping to a highlight scrolls to the stored anchor and briefly emphasizes the saved text range.
- **Delete**: use the trash control in the Highlights panel, or **click/tap the highlighted text in the body** and confirm removal.
- Implementation: `profileHighlightsStorage.ts`, `profileHighlightVisibleText.ts` (shared offset stream: skip inline `data-gospel-mount` text; **`plainTextForProfileHighlightUi`** for panel rows + new saves), `HighlightsDropdown.tsx`, `ProfileContent.tsx`, highlight wrapping in `GospelInlineHtml.tsx` (`<mark data-resource-highlight-id>` with **one mark per DOM block**—`<p>`, headings, `li`, **TipTap-style nested `<div>` lines**, `blockquote`; avoids invalid wraps that Safari/WebKit show as thin edge-only bars; **injected HTML uses a `display:contents` `div` host** so `<p>`/blocks stay in-tree under `[data-highlight-scope]` in WebKit; `data-resource-highlight-active` when focused), **`globals.css`** for paint (`!important` fill + `box-decoration-break: clone` so multi-line wraps stay visible in dark mode/Capacitor), and scope metadata from `GospelSection.tsx`.

### Profile body read aloud (`[slug]` pages)

- A **speaker** control in the sticky header (**between Help and Highlights**) opens **Listen** controls (**Play**/**Pause** and speed on one row; memorization practice keeps **Repeat** on a second row on a separate screen). The control is **not rendered on Android** user agents (Web Speech is unreliable there; same pattern as memorize passage TTS). Same component as memorize listen (`MemorizeListenControlsDialog`) with **`presentation="floating"`**: a card **just below the sticky header row** (**no dimmed backdrop**), **portaled to `document.body`**, with **`pointer-events-none`** outside the card so you can **scroll and interact with the page** while the controls stay visible. Memorize practice still uses the default **modal** presentation (dimmed backdrop, centered). Portaling keeps `position: fixed` viewport-relative (the sticky header’s `backdrop-filter` would otherwise trap fixed descendants). **Play** reads the **current table-of-contents block** in view (same scrollspy anchor as bookmarks: `getCurrentTocAnchorId` and `section-*` ids in `GospelSection.tsx`). When the last utterance for that block finishes **without error/cancel**, playback **automatically continues** to the **next** TOC entry that has readable text (`profileReadAlongNextAnchor.ts`): the page scrolls that block into view and queued speech proceeds; anchors nested **inside** a block you just finished (e.g. subsections under a top-level `section-N` you read as a whole) are **skipped** so the same paragraphs are not repeated. Spoken text is derived from the DOM: COMA / Four Rules **`[data-gospel-mount]`** content is omitted; **inline scripture** mounts and block **verse card** buttons speak the visible **reference** (`data-tour="scripture-card"`); other **buttons** (e.g. verse-pin chrome) are stripped. **`h1`–`h6`** heading text is **spoken** for most profiles; on **Spurgeon** (`sg…`), **Edwards** (`je…`), **Matthew Henry** (`mh…`), and **Luther Galatians** (`lgal`) CCEL profiles it stays **omitted** so section titles are not read twice (`isListenOmitHeadingProfileSlug` in `profileResourceListenText.ts`). Saved resume **fingerprints** can reset once for other profiles whose listen string changed. Content is **queued as chained utterances** (`splitTextForTtsChunks.ts`: sentences, then commas/colons, then word-wrapped runs); before each utterance, **`chapter:verse`** and **`chapter:verse-range`** patterns are rewritten for speech (e.g. `3:16` → `3 verse 16`, `12:1-3` → `12 verse 1 to 3`, `44:6-7a` → `44 verse 6 to 7a` so partial verses and hyphens are not heard as measurements; **`1`/`2`/`3` + book** tails like Corinthians or John become **first** / **second** / **third**; en dash between verses is treated like a hyphen; `bibleReferenceSpeechTransform.ts`) so engines are less likely to read them as clock times, while read-along still maps boundaries to **display** text offsets. Changing speed **between** chunks applies to the rest without restarting the section; **during** an active chunk, Web Speech cannot retime mid-utterance—the **current chunk is replayed** at the new speed (same fundamental browser limit). **Resume position** is saved **per profile slug + TOC anchor** in **`localStorage`** (`profileReadAlongProgressStorage.ts`, keys `gospel-profile-read-along:{slug}:{anchorId}`, plus **`gospel-profile-read-along-last:{slug}`** so returning after navigating away can resume the subsection where you stopped even when the viewport is scrolled to an earlier TOC block): debounced updates while speaking, flush on pause/unmount; a **fingerprint** of the section plain text drops stale saves after admin edits; completing the section clears storage; **Start from beginning** opens a **confirmation**; on confirm it clears read-aloud progress for **all** TOC anchors on this profile (device `localStorage`), scrolls to the **first readable TOC block** in presentation order, and starts playback at the top of that block. Otherwise, resume uses **chunk boundaries**—playback restarts at the beginning of the chunk that contains the saved offset, not mid‑sentence). While speaking, the page **scrolls only when needed** so the caret stays inside a comfort band below the sticky header (`scrollReadAlongPlain.ts`), avoiding vertical nudging on every word on wide lines; each chunk scrolls on **start** when that band needs adjusting (smooth when motion is allowed), and **`boundary`** updates use **instant** (`auto`) scroll only when the caret leaves the band so stacked smooth animations do not lag behind the fixed-position underlines; mapping walks the **same raw listen stream** as TTS (eligible `Text` nodes plus implicit `\n` between block-level siblings / across `<br>` / `<hr>`); **`listenCollapsedPlainFromRaw`** joins each implicit block boundary as a **single space** in the spoken plain string (so Web Speech `charIndex` stays aligned with audio for read-along); **`splitListenRawIntoTtsChunksWithOffsets`** (`splitTextForTtsChunks.ts`) splits the raw listen stream on `\n` first and marks the first chunk of each subsequent block with **pauseBefore** so playback waits **~95ms** before that utterance—headings and verse cards still get a breath **without** extra punctuation in the text. After an utterance whose **display** chunk ends in `.` `!` or `?`, the next chunk starts after a **~55ms** gap so sentence boundaries do not run together. **`walkerOffsetForReadAlongPlainOffset`** maps collapsed offsets into the raw listen walk (`scrollReadAlongPlain.ts`). DOM placement uses **`locateListenRawTextOffset`** on those raw indices (not the flat text-node count used for highlight *storage*), so multi-paragraph sections do not drift to the wrong line. **Reduced motion** uses instant scrolling. While speaking, an **amber underline** tracks read-along position: **Word** mode underlines the **current word**; **Line** mode underlines each **wrapped visual line** segment on the same row as the caret (layout via **`getClientRects()`** on the block from **`readAlongListenBlockAncestor`**). Both use Web Speech **`boundary`** data (`charIndex` / `charLength` in `readAlongSpeechWordRange.ts`, with whitespace token expansion when `charLength` is absent). Fixed-position underline segments are drawn in **`profileReadAlongDomHighlight.ts`** (**no edits** to article DOM), coalesced with scroll in **`requestAnimationFrame`**, with **scroll/resize** refresh. **`prefers-reduced-motion: reduce`** underlines the **whole chunk** instead of word-by-word or per-line. Underline scope follows **`charIndex`** expanded to **one whitespace-delimited word**; **`charLength`** is ignored because Chromium-class engines often report spans ahead of audio. Scroll nudging uses **`charIndex`** as well (not mid-word). Underline position trails **`getReadAlongWordsTrail()`** (heuristic: about **2** whitespace-delimited words on WebKit Safari / iOS, **4** on Chromium-class browsers, **3** elsewhere) behind Web Speech `charIndex`; boundary UI waits **`getReadAlongBoundaryUiLagMs()`** (~**90–100ms**, **0** with **reduced motion**) so the highlight stays near perceived speech without a true audio clock. **Safari** often provides sparse **`boundary`** metadata (and may omit **`name`**), so word tracking may be coarse there. The floating controls row keeps **Play**, **underline**, **Word**/**Line** (segmented, when underline is on), and **speed** on **one horizontal line** (`flex-nowrap` with horizontal scroll if the viewport is too narrow). **Read-aloud speed** is a **custom listbox** (button + options; **1px** slate borders and fills match **Play** / Word–Line on the same row), portaled with fixed positioning so the menu is not clipped by the row’s horizontal scroll; it shares **`localStorage`** `gospel-admin:memorize-listen-speed` with memorize listen. **Android** browser hosts do not run Web Speech here (same restriction pattern as memorize passage TTS). Code: `ProfileResourceReadAloud.tsx`, `MemorizeListenSpeedButton.tsx`, `useProfileResourceReadAloud.ts`, `profileResourceListenText.ts`, `readAlongSpeechWordRange.ts`, `readAlongBoundaryUiLag.ts`, `profileReadAlongDomHighlight.ts`, `profileReadAlongUnderlineStyleStorage.ts`, `profileReadAlongProgressStorage.ts`, `profileReadAlongNextAnchor.ts`.

### Read-to-end marks (presentation profiles)

- **Device-only** completion is stored in **`localStorage`** under **`gospel-presentation-read-complete:v1`** (`presentationReadCompleteStorage.ts`): JSON **`{ "v": 1, "slugs": string[] }`**. A slug is appended when **Listen** finishes the **last** TOC block with no further listenable anchor (`useProfileResourceReadAloud.ts` / `findNextReadAlongScope`), or when the reader **scrolls the window** to the **bottom** of the page once per visit (`usePresentationScrollReadComplete` in `ProfileContent.tsx`).
- **Resources** public-template links and **Spurgeon sermons** modal links use **extra-bold weight and slightly stronger text color** for slugs in that set (`TableOfContents.tsx`, `SpurgeonSermonsModal.tsx`). Updates broadcast on **`window`** as **`gospel-presentation-read-status-changed`** (`CustomEvent` detail `{ slug, read }`); **`storage`** events refresh lists when another tab changes the key.
- In the slide-out **Menu**, under **Pinned passages** (`data-tour="toc-verse-pins"`), **Mark this resource as unread** clears the current profile slug when it is complete.

## Scripture pins (highlighted cards)

On profile pages, readers bookmark passages with tinted pins for visual wayfinding: **one yellow** slot (“last verse viewed”) plus **many** tinted bookmarks (**red**, **blue**, **green**, **violet**) that can reuse the same color on different passages. Only **one** pin per passage (changing tint replaces any prior pin there). Pins are **device-only** (`localStorage` JSON `v:2`); they are not written to Supabase. Older payloads (`v:1`, `byColor`) migrate on first load.

**First-load migration (localStorage)**: If there is nothing under `gospel-verse-pins-{profileSlug}` but the old **`gospel-scripture-progress-{profileSlug}`** key still exists from the earlier single-slot progress store, **`loadVersePins`** copies that passage into the **yellow** slot, persists the new key, and removes the legacy key **only after** a successful verified write (so quota / storage failures cannot delete the legacy key before the migration is durable). Invalid legacy JSON is ignored (the stale key stays until cleared manually).

**Legacy note**: The `last_viewed_scripture` column and `GospelProfile.lastViewedScripture` in types remain in the schema and API for older data/admins but the **presentation viewer** no longer uses them for highlights or sync.

### Resources dropdown (public templates)
- The main page sidebar shows a Resources menu with public templates. Template titles use **extra-bold weight and darker slate** when that profile slug is in the read-to-end set (see **Read-to-end marks** above).
- **Bible Reader**: Admins can add a **Bible Reader** library row (at most one) in Admin → Settings → Resources dropdown order, same draggable pattern as **Morning & Evening** and other library rows (`type: bibleReader` in `public_template_order`). The row opens [`BiblePassagePickerModal`](gospel-admin/src/components/BiblePassagePickerModal.tsx) (same book / chapter / verse picker as **Memorize → + Add**). **Read** opens the scripture modal on the current profile—chapter view when only a chapter is chosen, verse or range when verses are selected. Wired from [`ProfileContent.tsx`](gospel-admin/src/app/[slug]/ProfileContent.tsx) via [`TableOfContents`](gospel-admin/src/components/TableOfContents.tsx) `onOpenBibleReader`. On profile pages, tapping the **reference in the scripture modal header** opens the same picker to jump to another passage. After a passage is chosen with the picker (Bible Reader or header), **Previous** / **Next** in the scripture modal step by verse or chapter within that book ([`biblePassagePickerNavigation.ts`](gospel-admin/src/lib/biblePassagePickerNavigation.ts)); opening from a presentation scripture card keeps the existing in-resource navigation.
- The study library modal (`SpurgeonSermonsModal`) has three tabs — **Search**, **By scripture**, and **By read**. **Search** lists **Sermons** (`/api/spurgeon/sermons`), **Edwards sermons** (`/api/edwards/sermons`), **Calvin commentaries** (`/api/calvin/books`), and **Matthew Henry commentaries** (`/api/henry/books`) in separate sections when `libraryFocus="all"`. **By scripture** lists **Sermons**, **Edwards**, **Morning & Evening**, **Calvin**, and **Matthew Henry** (`GET /api/spurgeon/by-reference`, `GET /api/edwards/by-reference`, `GET /api/morneve/by-reference`, `GET /api/calvin/by-reference`, `GET /api/henry/by-reference`). Following a **By scripture** hit opens the profile with **`?studyRef=`** (encoded lookup reference); after load, the page scrolls to the first matching subsection ([`findFirstStudyPassageAnchor.ts`](gospel-admin/src/lib/findFirstStudyPassageAnchor.ts): scripture cards and subsection titles first—important for Calvin unit headings—then **chapter-level** Matthew Henry / Calvin titles such as **`Romans — Chapter 8`** or **`Psalm 51`** when the open verse is in that chapter, then inline body refs; [`scrollToTocAnchorWhenReady`](gospel-admin/src/lib/scrollToTocAnchor.ts) retries until the anchor is in the DOM). - **First visit welcome**: The first time someone opens a gospel **profile** page in this browser (`ProfileContent`), a **Welcome** dialog offers **Start full walkthrough** or **Close**. Dismissal is stored in **`localStorage`** (`gospel-presentation-first-visit-welcome-v1` via `presentationWelcomeStorage.ts`). **Close**, clicking the dimmed backdrop, or **Escape** closes the dialog and briefly highlights the **Help** (`?`) control (`PresentationFirstVisitWelcome`). **Start full walkthrough** saves the same flag and runs `runFullProfileHelpTutorial`. The overlay is a **`fixed inset-0`** layer with the **semi-transparent background on that node** (so the whole viewport stays dimmed), then a **`min-h-dvh` grid** centers the card; safe-area padding and optional body scroll inside the card help **Safari / iOS** and larger text sizes.
- **Header control**: On `[slug]` profile views, header controls on the right run **Help** → **Listen** (speaker, omitted on Android) → **Highlights** → **bookmark** icon → **Share this resource** → **theme** toggle. The bookmark, share, help, read-aloud, highlights, theme, and **menu (hamburger)** controls use the same chip styling as each other; the menu control may include the visible word **Menu** when there is room (see sticky-header bullet above). **Light mode** uses soft **slate-200 / hover slate-300** with **slate-800** icons; **dark mode** uses **slate-600 / hover slate-700** with white icons. The dropdown panel (styling aligned with the TOC text-size controls) opens **directly under the icon**. On viewports **below the `md` breakpoint** (~768px), the panel is **horizontally centered** on the screen; on wider screens the panel’s **right edge aligns to the icon** so it opens **leftward**. Position updates on scroll/resize while open. While open, a **dimmed full-viewport backdrop** (fades in) is rendered via a **portal to `document.body`** so it covers the whole page (the sticky header’s `backdrop-blur` would otherwise clip `position: fixed` children to the header); tap/click outside closes it on all breakpoints.
- **Add**: **+ Add bookmark** saves the current resource (`profile` title and slug), the best-matching **table-of-contents anchor** (same `section-*` ids as the TOC), a short location label, and your **reading line inside that section** (same collapsed plain-text position model as **Listen** / read-along: `plainOffset` + content fingerprint in [`profileReadingPosition.ts`](gospel-admin/src/lib/profileReadingPosition.ts)). An optional **excerpt** expands with a **chevron** on the row (resource title and one-line location always visible). Data is stored in **IndexedDB** (`gospel-profile-bookmarks` schema v2 via `gospelClientStorage.ts`); duplicate slug + anchor + offset is ignored (“Already saved”). Legacy bookmarks without an offset still open at the section top. Below **Add bookmark**, a **debounced search** box (same styling as the Highlights panel) filters saved rows by resource title, location label, excerpt, profile slug, and anchor id.
- **Open**: Tapping a bookmark scrolls to the saved anchor and, when a fingerprint still matches, restores the in-section reading line to the same viewport read line used when saving (sticky header + 24px; not the wider **Listen** read-along comfort scroll) via [`restoreReadingPosition`](gospel-admin/src/lib/profileReadingPosition.ts). On the current page that is immediate; for another profile the app uses **`router.push`/`#hash`** plus a one-shot **sessionStorage** resume payload (hash alone cannot encode offset). Plain `#section-*` deep links still scroll to the section top via [`scrollToTocAnchor`](gospel-admin/src/lib/scrollToTocAnchor.ts).
- **Automatic resume**: While you read, scroll position is saved per profile slug in IndexedDB (`gospel-profile-reading-resume:{slug}` via [`profileReadingResumeStorage.ts`](gospel-admin/src/lib/profileReadingResumeStorage.ts)), debounced after scrolling stops. When you return to a profile (no competing `#section-*` hash, `?studyRef=`, or M'Cheyne plan/resume query), the app restores that position with the same read-line alignment as bookmarks if the content fingerprint still matches; otherwise the stale entry is cleared. Included in **Save my data** / **Restore my data**.
- **Remove**: Each row has a remove control; confirmation uses the same app confirm modal as other actions.

## Native app (Capacitor)

The app is wrapped for iOS and Android via Capacitor (WebView loads the deployed site).

- **Tutorial navigation**: Scripture-reader tour jumps to `/default` and the full-walkthrough **thank-you** return to the stored profile slug use **`router.push`** on native (`CapacitorProfileHelpTourNavigation` in `layout.tsx` registers with `scriptureReaderTourNavigation.assign` in `profileHelpTours.ts`) so those moves stay in the WebView instead of opening the system browser.

- **Splash screen (iOS)**: On launch, the iOS app shows a centered app icon on a solid background (Launch Screen) and keeps it visible until the web app has loaded. This avoids a black screen between the system launch screen and the first painted content. Implemented with `@capacitor/splash-screen` (`launchAutoHide: false`) and `SplashScreenController` calling `SplashScreen.hide()` once the app is ready; the launch screen is defined in `ios/App/App/Base.lproj/LaunchScreen.storyboard` and uses the `LaunchIcon` image set (same graphic as the app icon). Changing the launch screen or splash behavior requires a **native rebuild** (e.g. `npx cap sync` then build in Xcode).
